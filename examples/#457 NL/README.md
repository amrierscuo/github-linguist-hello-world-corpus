# #457 NL

Voce canonica `NL`, tipo `data`, language_id `241`.

Rappresentare i 13 codici ASCII del saluto come variabili vincolate in un autentico modello AMPL NL.

## Toolchain e riproduzione

Pyomo native AMPL NL writer (reader/solver pending) — 6.9.5. Ambiente della prova: **Windows x64, Ubuntu 24.04 WSL2 for Linux tools**.

Pyomo 6.9.5 genera il formato NL. Per leggere/risolvere serve un vero driver solver AMPL/ASL capace di NL, non una build generica di HiGHS.

Comando/procedura dalla directory dell’esempio, salvo indicazioni esplicite:

```text
python model.py build/hello.nl; highs build/hello -AMPL
```

Risultato atteso: Il solver legge il modello, restituisce i 13 valori vincolati, che ricostruiscono Hello, World!.

## Stato ed evidenza

Artefatto **creato**; sintassi **in attesa**; semantica **in attesa**.

hello.nl è stato generato dal writer NL reale di Pyomo e la rigenerazione produce byte identici. Ogni carattere è un vincolo numerico; non è un saluto in un commento. Un reader/solver indipendente manca, quindi entrambi i flag restano false.

Requisiti residui:

- Original NL generated by Pyomo writer; an independent native NL reader/solver is unavailable. Official AMPL solver-module download endpoint returned HTTP 403. Syntax and solve semantics remain pending.

Log reale: [native.json](verification/native.json), con comandi, versioni, exit code,
stdout/stderr e SHA-256 degli artefatti. `path_normalization` descrive le sole
sostituzioni dei percorsi locali; `<corpus>` identifica i sorgenti finali verificati
prima in staging. I soli probe di disponibilità non attestano parsing o esecuzione.
Dipendenze e prodotti compilati rimangono nella directory di lavoro.
